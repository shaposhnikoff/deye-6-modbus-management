# Runbook: изменение одного параметра на инверторе

> English version: [RUNBOOK-WRITE.md](RUNBOOK-WRITE.md)

Короткая процедура для оператора в shell на Pi. Цель: изменить разрешённый параметр, доказать, что
он применился, и иметь возможность откатить изменение.

## Что такое «запись»

На инверторе ничего не выполняется. Каждое значение отправляется одним кадром Modbus RTU **FC16**:
slave `1`, адрес регистра, одно 16-битное слово, CRC. Единственная команда человека:

```bash
dmon-write set <key>=<value> --confirm
```

Утилита проверяет ключ по allow-list, валидирует диапазон, пишет регистр, сравнивает эхо, читает
регистр обратно и добавляет JSON-строку в `/var/log/deye/writes.log`. Без `--confirm` она только
печатает план и ничего не пишет.

## Что можно менять

Только Time-of-Use регистры 250–279. `N` — номер слота, 1–6.

| Ключ | Смысл | Формат | Диапазон |
|---|---|---|---|
| `tou.N.start` | начало слота | HHMM, например `2300` | 0000–2359, минуты < 60 |
| `tou.N.power` | мощность слота | ватты | 0–12000 |
| `tou.N.voltage` | целевое напряжение батареи | вольты (на шине 0.01 В) | 40–60 |
| `tou.N.soc` | целевой заряд | проценты | 10–100 |
| `tou.N.grid_charge` | разрешить заряд от сети в слоте | `0` / `1` | — |
| `tou.N.gen_charge` | разрешить заряд от генератора | `0` / `1` | — |
| `tou.N.charge_mask` | всё битовое поле заряда | 0–31 | **непроверено**, нужен `--include-unverified` |

Всё остальное отклоняется с кодом выхода `2`. Битовые ключи пишутся через read-modify-write,
поэтому биты `gm/bu/ch` и остальные биты заряда сохраняются.

## Перед началом

- сеть стабильна, инвертор не в ошибке и не обновляет прошивку;
- точные целевые значения известны и записаны;
- всё окно займёт меньше двух минут (Prometheus поднимет `DeyeDataStale` через две);
- `/var/log/deye` существует и принадлежит `max` (разово:
  `sudo install -d -o max -g max /var/log/deye`);
- на шине больше никого нет.

## Процедура

```bash
ssh max@192.168.10.39
cd /home/max/DEYEMonitoring
```

**1. Освободить последовательный порт.** Коллектор держит его эксклюзивно, поэтому любая команда
`dmon-write` падает, пока сервис запущен.

```bash
sudo systemctl stop deye-monitoring
```

**2. Прочитать текущие значения.**

```bash
.venv/bin/dmon-write list
```

**3. Сухой прогон.** Печатает, что изменится, и ничего не пишет.

```bash
.venv/bin/dmon-write plan tou.1.power=5500
```

Проверь строку `before -> after`. Если это не то, что нужно, остановись здесь.

**4. Применить.**

```bash
.venv/bin/dmon-write set tou.1.power=5500 --confirm
```

Каждый ключ должен напечатать `ok ... verified by readback`. Код выхода `0` означает, что прошли
все.

**5. Проверить read-only.**

```bash
.venv/bin/dmon-write verify tou.1.power=5500
```

Ожидается `1/1 match`. Эту команду стоит повторять позже, чтобы ловить дрейф.

**6. Вернуть порт.** Делай это даже если шаг 4 упал.

```bash
sudo systemctl start deye-monitoring
curl -s localhost:9101/health
```

Ожидается `"ok": true`.

**7. Проверить audit log.**

```bash
tail -n 3 /var/log/deye/writes.log
```

Одна строка на ключ, с `from_raw`, `to_raw`, `confirmed: true` и серийником инвертора.

**8. Проверить на устройстве.** Меню самого инвертора — источник истины. Если экран расходится с
readback, остановись и разберись, прежде чем доверять утилите.

## Пример: ночное окно зарядки (уже применено)

Шесть слотов, заряд от сети разрешён только 23:00–07:00. Двигаются два регистра старта, потому что
границы 07:00 раньше не было, и сбрасываются четыре бита grid:

```bash
sudo systemctl stop deye-monitoring
.venv/bin/dmon-write plan \
  tou.6.start=2300 tou.2.start=700 \
  tou.1.grid_charge=1 tou.2.grid_charge=0 \
  tou.3.grid_charge=0 tou.4.grid_charge=0 \
  tou.5.grid_charge=0 tou.6.grid_charge=1
# всё верно? повтори те же ключи с `set ... --confirm`
.venv/bin/dmon-write verify \
  tou.6.start=2300 tou.2.start=700 \
  tou.1.grid_charge=1 tou.2.grid_charge=0 \
  tou.3.grid_charge=0 tou.4.grid_charge=0 \
  tou.5.grid_charge=0 tou.6.grid_charge=1
sudo systemctl start deye-monitoring
```

Полная запись, включая значения для отката, — в
[2026-10-21-tou-night-charge.md](plans/2026-10-21-tou-night-charge.md).

## Откат

Audit log хранит предыдущее сырое слово в `from_raw`. Верни старое значение:

```bash
sudo systemctl stop deye-monitoring
.venv/bin/dmon-write set tou.1.power=5000 --confirm   # значение из from_raw
sudo systemctl start deye-monitoring
```

Для битовой цели `from_raw` — это целое слово, а `set` принимает значение бита (`0`/`1`). Старое
значение бита смотри в `dmon-write list` или на экране инвертора.

## Диагностика

| Симптом | Причина | Действие |
|---|---|---|
| `serial error ... busy` | коллектор всё ещё работает | `sudo systemctl stop deye-monitoring`, повторить |
| `no reply for write at 0x....` | инвертор выключен/в ошибке или прошивка игнорирует FC16 | проверь, что `dmon-write list` ещё читает; проверь питание и провода A/B |
| `inverter rejected read ... illegal data address` | неверная база регистров для этой прошивки | не форсировать; сверься с экраном инвертора |
| `echo mismatch` | помехи на линии или второй master | `pgrep -af "bin/dmon"`, оставь одного владельца, повтори один раз |
| `FAILED ... wrote X, read back Y` | значение не принято | проверь диапазон, затем экран |
| `warning: could not write audit log` | нет `/var/log/deye` | `sudo install -d -o max -g max /var/log/deye` |
| команда завершилась, а сервис лежит | SSH оборвался посреди окна | переподключись, `sudo systemctl start deye-monitoring` |

Коды выхода: `0` — успех, `1` — ошибка транспорта/порта, `2` — отказ (неизвестный ключ или выход
за диапазон), `3` — не прошла проверка readback.

## Правила

- Одна группа параметров на команду; регистры времени и их биты можно вместе.
- `set` без `--confirm` всегда безопасен — используй его как последнюю проверку.
- Записи абсолютные: повторный запуск той же команды безопасен и идемпотентен.
- Никогда не вызывай `dmon-write set --confirm` из cron, скрипта или Home Assistant. Это делает
  человек.
- Если запись применилась частично, повтори ту же команду и затем `verify`.
